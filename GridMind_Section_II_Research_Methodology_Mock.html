II. REVIEW PROTOCOL AND METHODOLOGY

This review examines the research basis for the five AI functions planned for GridMind: missing-telemetry reconstruction, demand and renewable forecasting, event diagnosis, cascade-risk prediction, and corrective-action recommendation. The five functions are treated as related tracks within one project-wide literature review. Evidence is organized by function during extraction and then synthesized against the proposal’s five shared research questions. A review protocol should be finalized before any additional searching or screening and retained with a version date so that decisions can be traced.

The initial candidate corpus was assembled in the GridMind research Markdown files and supplied article PDFs. These materials are the starting set for screening and extraction; their presence in a project file alone does not establish that each source meets the review’s eligibility criteria. The protocol below describes how the team will assess this existing set and record any supplementary searches that are actually performed.

Studies will be assessed against criteria defined for the project-wide scope. A study may address one or more GridMind functions, but its contribution and function tag will be recorded separately. The same rule will be applied to all candidate studies.

B. Search Strategy

The existing project corpus will first be inventoried from the five model files and associated paper PDFs. The team will record each paper’s bibliographic details, the model file in which it is discussed, and whether the full text is available. To improve coverage beyond the papers already collected, searches may be run in IEEE Xplore, ACM Digital Library, Scopus, Web of Science, and SpringerLink, with Google Scholar used as a supplementary discovery source. Only databases actually searched should be named in the final proposal.

Search terms will be adapted to each function. The following are example query structures to finalize and execute; they are not a record of searches already run:

For every executed query, the search log will preserve the database, exact query string, filters, date searched, and number of records exported. Queries may be adjusted for each database’s syntax, but all changes will be recorded. Backward and forward citation checks may be used to identify relevant studies and must be logged separately.

C. Study Selection Process

  1. Inventory and deduplication: compile the papers already cited in the GridMind files and supplied PDFs; match duplicate versions by title, authors, DOI, or preprint identifier; retain the most complete accessible version and note related versions.
  2. Title and abstract screening: apply the inclusion and exclusion criteria to each unique candidate. Assign one or more function tags and record an exclusion reason where excluded.
  3. Full-text screening: assess the remaining papers against the same criteria and confirm that the reported work is relevant to at least one research question.
  4. Decision review: where possible, two team members independently screen borderline studies and resolve disagreements by discussion. If only one reviewer is available, document that limitation rather than implying dual screening.
  5. Reporting: populate a PRISMA-style flow diagram from the actual search and screening log. Do not estimate or infer counts from the number of files currently present.

E. Data Extraction and Synthesis

One row will be completed for each included research study. Dataset pages, repositories, standards, and project handover documents may be recorded in a separate resources list, but will not be counted as empirical research papers unless they themselves report an eligible study.

FieldInformation to extract

EvidenceDataset/network, sample size where stated, preprocessing, baselines, split protocol
EvaluationMetrics, reported results, validation setting, comparison conditions
AssessmentKey strengths, limitations, quality scores, relevance to GridMind, extraction notes

Evidence will first be summarized within each model track to preserve differences in task, data, and metrics. It will then be compared across the project under the five shared research questions: state of the art; methods and data; tools and resources; gaps and limitations; and evidence-based directions for GridMind. Narrative and thematic synthesis will be used because the five functions use different prediction targets and evaluation measures, so a single pooled performance comparison would not be meaningful. Paper-reported findings will be distinguished from GridMind design proposals and from results produced by the GridMind implementation.
